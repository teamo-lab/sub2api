# 账号尝试分组与切换次数筛选

单请求保留原总时间线，下方增加“账号 / 渠道阶段”及比例总览条：入口准备单列；每个 attempt_start 到下一次 attempt_start（末次到请求结束）是一段，同账号 retry 也单独成组。每段显示尝试序号、首次/重试/切换标签、账号当前名称、渠道 ID、绝对起止时间与区间长度。分段条各自放大；点击子阶段显示请求内绝对时间。下一次尝试前的退避和准备保留在前一段，界面明确说明，这些区间不等于账号纯计算时长。微秒精度下的零时长尝试保留，不悄悄减少尝试数。

新增“切换次数”标签与筛选：全部（参数省略或空）、0、1、2、3+，统计 retry + fallback 事件，不包含 local_reselect。列表、数量、P90 和聚合图共享同一 SQL 过滤条件，筛选不限于当前页。0 是有效值，不与空值混用。

历史重建、记录截断、并行上游的切换次数为未知，不纳入精确次数筛选；不完整尝试边界及 WebSocket 会话不强行划分串行账号组。旧数据无需回填，具备完整 attempt_start 的记录即可分组。名称只按当前页涉及 ID 一次性查询，无逐条 N+1；使用当前名称而非请求发生时名称快照，已删除/无名称账号保留 ID 并显示名称不可用。

无采集/网络/流处理/重试策略修改，无数据库迁移；前后端一起发布。
