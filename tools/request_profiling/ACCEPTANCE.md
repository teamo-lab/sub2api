# 本地验收记录

基线为 `teamo/main` 的 `c5d383f65`，独立分支 `codex/request-profiling-panel`。本地真实后端、独立 PostgreSQL 数据库、Redis 和 Vite 前端运行；未连接生产凭据、未发布生产。

## 已验证

- 完整后端回归：config、requestprofile、httputil、middleware、service、handler、admin handler、repository、server 全部通过。另验证 recorder/middleware race、真实 PostgreSQL 临时表中的聚合与筛选。
- 选号/凭据最后补点后，相关 service 回归再次通过，重新构建并在真实请求中确认这两个阶段存在。
- 前端类型检查、ESLint、7 个组件/页面测试、生产构建通过。
- 管理 API 未认证访问返回 401。聚合使用同一数据库快照；分页不改变分母；按切换前账号仍能查到请求。
- 真实本地网关调用：受控 503 → 账号切换 → 受控 400 → 同账号修复重试 → 有效输出和完成。轨迹记录 3 次尝试、1 次 retry、1 次 fallback。本机准入重选不计入这两个计数。
- 重复执行时调度可能直接避开暂时不可用的测试账号；最后补点验证记录到 2 次尝试（400 → 200），没有伪造不存在的 fallback。
- 断连反例：调用方约 1.07 秒断开，后台约 3.19 秒结束。HTTP 状态虽然为 200，profile 显示连接取消、约 2.12 秒断连后后台处理、没有有效输出和完成事件写出。后台后续结果未覆盖客户侧观测。

## 浏览器交互与视觉验收

在原生 Chrome 的 `http://127.0.0.1:5187/admin/request-profiling` 中完成并查看截图：

1. 从侧栏进入独立页面，加载、刷新与空状态可用；无样本时显示“—”。
2. 在固定时间窗口内联合选择模型、分组和渠道，历史 astra 的 3 条请求聚合平均 108.20 秒、P90 171.53 秒，与原始计算一致。
3. 打开约 39 MB 的真实历史长尾，放大旧观测点之前，点击跨机区间，读到 1.16 秒；阶段表有直接耗时及起止位置，不要求用户心算相减。
4. 历史来源明确显示“非函数级实测”、缺失 retry/fallback 元数据、跨机时钟限制；不混入当前实测分母。
5. 当前实测中，账号切换和同账号重试以不同关键节点展示；完成事件写出与上游观测分开。
6. 取消反例显示红色取消节点与灰色断连后处理段，不能将 HTTP 200 或后台成功当客户成功。
7. 无效分组 0 明确报错，不退化成全量；不存在模型显示空结果，恢复筛选后正常加载。
8. 修改筛选保持同一完成时间窗口，避免跨模型/分组比较时窗口悄悄漂移。

历史原始请求 ID、完整元数据、凭据、运行日志和截图中的私有原始内容不提交到仓库。验收所用私有材料保留在本机；模拟上游及本地验收脚本可用于重复验证。

## 明确边界

- 本服务端写出/flush 不是远端接收 ACK；未覆盖的语义交付路径保持未知。
- WebSocket 明确按连接并标识轮次，不能将长连接存续时间冒充单次 response 延迟。
- 并行 span 不重复求和；并行上游调用不凭顺序推断重试。截断和日志 sink 丢弃状态公开展示。
- 本 PR 提供诊断能力，不宣称生产 3～4 秒损耗已被优化或已经取得生产收益。
